# PROMPT 4.1.1: Prototype Testing Strategy & Plan

Use Case: Planning comprehensive prototype testing approach

```text
I need to test my solution concept with users/customers before fully implementing it. Help me create a testing strategy.

MY SOLUTION CONCEPT:
[DESCRIBE YOUR SOLUTION - e.g., "A new step-by-step guidance system that provides contextual help during complex tasks" or "A redesigned workflow that eliminates manual data entry" or "A real-time tracking dashboard for monitoring progress"]

KEY HYPOTHESES TO TEST:
1. [HYPOTHESIS 1 - e.g., "Users will find the new guidance more helpful than current approach"]
2. [HYPOTHESIS 2 - e.g., "The redesigned process will reduce errors by 30%"]
3. [HYPOTHESIS 3 - e.g., "Users will trust the new system's outputs"]

Create a comprehensive testing strategy:

1. TESTING OBJECTIVES
   - What do we need to learn from testing?
   - What decisions will this testing inform?
   - What would make us pivot or change direction?
   - Success criteria for the test

2. WHAT TO TEST vs. WHAT NOT TO TEST
   - Core assumptions that MUST be validated
   - Nice-to-know vs. need-to-know
   - What can wait until later testing phases?
   - Prioritized list of testing goals

3. PROTOTYPE FIDELITY RECOMMENDATION
   - What's the right fidelity level for this stage?
   - Options to consider:
     * Paper prototype/sketches
     * Clickable wireframes (low fidelity)
     * High-fidelity mockups
     * Functional prototype
     * Wizard of Oz (fake the backend)
     * Concierge MVP (manually deliver the service)
   - Recommend approach based on what we're testing
   - Pros/cons of recommended approach

4. PROTOTYPE SCOPE
   - What parts of the solution to include in prototype?
   - What to simulate vs. actually build?
   - What user flows to include?
   - What scenarios to test?
   - What can be represented with placeholder content?

5. TESTING METHODS TO USE
   Which methods are appropriate:
   - Usability testing (think-aloud protocol)
   - Concept testing (show and get feedback)
   - A/B testing (compare alternatives)
   - Wizard of Oz testing (simulate functionality)
   - Desirability testing (reaction to value proposition)
   - Recommend best mix of methods

6. PARTICIPANT RECRUITMENT
   - How many participants needed? (typically 5-8 for usability)
   - What mix of user types? (personas, segments)
   - Recruitment criteria
   - How to recruit (similar to empathy interviews)
   - Incentive recommendation

7. TEST SCENARIOS & TASKS
   - Realistic scenarios to give participants
   - Example: "Imagine you need to [complete a key task in your solution]..."
   - Specific tasks to ask them to complete
   - How to set context without biasing

8. TEST SCRIPT STRUCTURE
   Outline of testing session:
   - Introduction and consent (5 min)
   - Background questions (5 min)
   - Prototype interaction (20-30 min)
   - Post-test questions (10-15 min)
   - Wrap-up (5 min)

9. OBSERVATION & MEASUREMENT
   What to observe:
   - Task completion rates (did they succeed?)
   - Time on task
   - Error rates and recovery
   - Hesitations and confusion points
   - Emotional reactions (frustration, delight)
   - Spontaneous comments
   - What they expect vs. what happens

   What to ask:
   - Ease of use (rating scale)
   - Value perception (would you use this?)
   - Trust and confidence
   - Comparison to current experience
   - What they liked/disliked
   - What's missing or confusing
   - Open-ended feedback

10. SUCCESS METRICS
    How to know if concept is validated:
    - Quantitative thresholds (e.g., "80% can complete task")
    - Qualitative signals (e.g., "participants express enthusiasm")
    - Red flags that would invalidate concept
    - Criteria for "go/no-go" decision

11. ITERATION PLAN
    - How many testing rounds? (typical: 2-3 iterations)
    - What triggers next iteration? (major issues found)
    - When have we tested enough?
    - How to incorporate feedback between rounds?

12. LOGISTICS & TIMELINE
    - Duration per test session
    - Number of sessions per week (don't burn out)
    - Total timeline for testing phase
    - Team roles (facilitator, observer, note-taker)
    - Equipment and materials needed

13. ANALYSIS APPROACH
    After testing:
    - How to synthesize findings across sessions?
    - How to prioritize issues found?
    - How to decide what to fix vs. accept?
    - How to communicate results to stakeholders?

OUTPUT FORMAT:
Complete testing plan with:
- Clear objectives and success criteria
- Prototype recommendation with rationale
- Participant recruitment plan
- Test script outline
- Observation checklist
- Success metrics
- Timeline and logistics plan
```

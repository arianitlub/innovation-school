# PROMPT 4.3.2: Landing Page Prototype Builder

Use Case: Building a polished, interactive landing page HTML prototype for user testing

Note: section 8 asks for stock images, but section 13 forbids external images. Use inline SVG/CSS illustrations so the file stays self-contained.

```text
You are an experienced product designer, UX/UI designer, UX writer, product owner, and front-end developer.

Your task is to create a polished, realistic, interactive landing page prototype for the solution described below.

The landing page will be shown to and potentially tested with real users. It must therefore feel like a credible, professionally built marketing/product page that could actually exist, not like a wireframe, internal concept, consulting slide, or technical demo.

==================================================
1. PRODUCT CONTEXT
==================================================

SOLUTION:
[Describe the overall solution in 3-5 sentences]

CORE PROBLEM:
[What user problem are we solving?]

TARGET USER / AUDIENCE:
[Describe the primary persona, their situation, needs, and level of knowledge]

CORE VALUE PROPOSITION:
[What is the main benefit for the visitor?]

PRIMARY CONVERSION GOAL:
[What action should the visitor take? e.g., sign up, book a demo, start a free trial, download, contact sales]

CONTEXT OF USE:
[When, where, and why would someone land on this page? e.g., paid ad, referral, search, email campaign]

ASSUMPTIONS TO TEST:
[Optional: What hypotheses should this landing page help validate? e.g., message-market fit, willingness to sign up, which value proposition resonates most]

==================================================
2. LANDING PAGE OBJECTIVE
==================================================

Design the page around the visitor's goal and decision journey rather than around the organisation's internal structure.

The page should:

- Make the value proposition understandable within the first 5 seconds (above the fold)
- Immediately answer "What is this?", "Who is it for?", and "Why should I care?"
- Guide the visitor naturally toward one clear primary action
- Minimise cognitive load and distractions
- Make complex topics feel simple and credible
- Build trust progressively as the visitor scrolls
- Show realistic content rather than placeholder text
- Demonstrate the core value proposition through concrete examples, not just claims
- Address likely objections before the visitor has to ask
- Always point toward the same clear next step
- Feel like a coherent, single product story from top to bottom

Prioritise persuasion and clarity. Do not add sections simply to make the page look more sophisticated.

==================================================
3. PAGE STRUCTURE & FLOW
==================================================

Before building, internally determine the simplest narrative that convinces the visitor to take the primary action.

Create approximately 7-9 meaningful sections.

A typical structure could include:

1. Header / navigation bar
2. Hero section (value proposition + primary CTA)
3. Problem / pain point framing
4. Solution overview / how it works
5. Key benefits or features (concrete, not generic)
6. Social proof (testimonials, logos, numbers, case studies)
7. Objection handling / FAQ
8. Pricing or offer (if relevant)
9. Final call-to-action section
10. Footer (links, legal, contact)

Adapt this structure to the specific solution rather than following it mechanically.

Each section must have:

- One clear purpose
- One dominant message
- A natural visual and narrative transition to the next section
- Minimal competing information

The visitor should never wonder:
- What is this page about?
- Is this relevant to me?
- What am I being asked to do?
- What happens if I click this?

==================================================
4. UX WRITING & COPYWRITING
==================================================

Write all visible page copy as part of the product design.

Apply these principles:

CLARITY OVER CLEVERNESS
Use direct language that immediately communicates meaning.

BENEFIT-LED, NOT FEATURE-LED
Lead with outcomes for the visitor, support with features.

CONCISE
Remove unnecessary words. Headlines should be scannable in seconds.

ACTIVE VOICE
Tell visitors clearly what they get and what to do.

CONVERSATIONAL BUT CREDIBLE
Write like a knowledgeable, trustworthy human, not a hype machine.

ACCESSIBLE
Avoid jargon and unexplained terminology.

SPECIFIC
Use concrete numbers, outcomes, and examples instead of vague claims.

Examples:

BAD:
"Innovative solutions for your business"

BETTER:
"Cut your monthly reporting time from 3 days to 20 minutes"

BAD:
"Submit"

BETTER:
"Start my free trial"

BAD:
"We offer great support"

BETTER:
"Get a real answer from a human in under 2 hours"

Do not expose internal terminology, technical architecture, product-management language, banking jargon, compliance terminology, or consulting language unless it builds credibility for this specific audience.

Do not end short headlines, button labels, or nav items with full stops.

==================================================
5. SECTION CONTENT
==================================================

For every section, create realistic production-quality content including where relevant:

- Headline
- Subheadline / supporting text
- Primary CTA
- Secondary CTA (if any)
- Navigation links
- Feature/benefit cards with icons
- Testimonials with names, roles, and companies (clearly fictional)
- Statistics or proof points
- FAQ questions and answers
- Pricing tiers (if relevant)
- Trust signals (security, certifications, partners)
- Footer links and legal notes

Do not use Lorem Ipsum.

Do not leave generic placeholder content such as:
"Feature 1"
"Lorem ipsum"
"Company Name"
"John Doe, CEO"

The landing page should contain enough realistic content that someone could genuinely evaluate and react to the concept.

==================================================
6. CTA & INTERACTION DESIGN
==================================================

Use action-oriented, outcome-specific CTAs.

Prefer:

"Start my free trial"
"See it in action"
"Get my personalised quote"
"Book a demo"
"Check if I qualify"
"Download the guide"
"Talk to an expert"

Avoid vague labels such as:

"Submit"
"Learn more"
"Click here"
"Next"

unless the context makes their outcome completely obvious.

The primary CTA should repeat at logical points down the page (hero, after benefits, after social proof, final section) and always lead to the same clear action.

Navigation links, FAQ accordions, pricing toggles, tabs, and CTA buttons should be interactive.

Interactions should visibly change the interface.

Where helpful, include:

- Sticky header on scroll
- Expand/collapse FAQ accordion
- Pricing toggle (monthly/annual)
- Tabbed feature showcase
- Form validation on a signup/contact form
- Success confirmation after form submission
- Smooth scroll to sections via nav/anchor links
- Hover and active states on cards and buttons

Avoid creating interactions that do nothing.

==================================================
7. FORM, SUCCESS & EMPTY STATES
==================================================

LEAD CAPTURE / SIGNUP FORM

Keep it short, only ask for what is necessary at this stage.

Structure validation errors around:

1. What happened
2. What the visitor can do to fix it

Example:

BAD:
"Invalid input."

GOOD:
"That doesn't look like a valid work email. Try again?"

SUCCESS / CONFIRMATION STATE

Confirm:
1. What was completed
2. What happens next
3. What the visitor can do now (e.g., check inbox, book a time)

EMPTY / FALLBACK STATES

Never show an unexplained blank area (e.g., no testimonials loaded, no pricing selected).

Explain clearly what is shown by default and why.

==================================================
8. VISUAL DESIGN
==================================================

Create a premium, modern, trustworthy marketing page.

Design principles:

- Clear visual hierarchy guiding the eye down the page
- Generous whitespace
- Strong, confident hero section
- Rounded cards and controls
- Soft shadows used carefully
- Clear, scannable typography with a defined heading scale
- Short, readable content blocks
- Consistent spacing and alignment across sections
- Visually obvious, repeated CTAs
- Subtle depth and motion (hover states, fade/slide on scroll where appropriate)
- Minimal clutter
- High perceived quality, suitable for a real product launch
- Use stock images where it makes sense (e.g. hero section, testimonials, lifestyle/context shots) to add credibility and warmth, rather than relying only on icons and illustrations
- The page should immediately communicate what the offering is, who it is for, and why it is valuable, without overwhelming the visitor
- Design the page around the user's perspective and needs, rather than around internal structures or product features

BRAND / VISUAL DIRECTION:

Primary accent:
RBI-style yellow

Primary text/navigation:
Black or near black

Background:
Warm off-white / very light neutral

Supporting colours:
Muted neutral tones with restrained use of status colours

Overall feeling:
Modern financial technology meets friendly digital guidance

Avoid:
- Corporate PowerPoint aesthetics
- Dense, data-heavy layouts
- Excessive gradients
- Tiny typography
- Walls of explanatory text
- Too many competing CTAs on one screen
- Overuse of icons
- Decorative elements without a purpose

==================================================
9. RESPONSIVE PRESENTATION
==================================================

Present the prototype as a realistic, responsive marketing website.

- Design desktop-first, since most landing page traffic and stakeholder review happens on larger screens
- Ensure the layout adapts cleanly to tablet and mobile breakpoints
- Stack multi-column sections vertically on narrow viewports
- Keep the header/navigation usable on mobile (e.g., collapsible menu)
- Keep the primary CTA visible and reachable at every breakpoint
- Give the surrounding presentation enough breathing room; the page itself should be the dominant visual element

The experience itself must remain fully responsive, not just resized.

==================================================
10. NAVIGATION
==================================================

Use a simple header navigation appropriate to a landing page.

Use approximately 4-6 anchor links to key sections, plus a primary CTA button in the header.

For this concept use:

[INSERT NAVIGATION ITEMS]

Example:
- Product
- How it works
- Pricing
- FAQ
- Log in
- Get started (CTA button)

Clicking a nav item should smoothly scroll to the relevant section.

On mobile, collapse navigation into a menu that still works.

==================================================
11. TRUST & GUIDANCE
==================================================

Because this is a business-oriented product, communicate trust through design, proof, and content rather than through excessive disclaimers.

When information touches financial, tax, legal, regulatory, or similarly sensitive topics:

- Clearly distinguish marketing claims from professional advice
- Do not present fictional results or testimonials as verified facts
- Make any assumptions or conditions visible (e.g., "results vary", eligibility criteria)
- Explain why any sensitive information is requested in a form
- Give the visitor control over what they share and when

Any fictional companies, testimonials, logos, statistics, pricing, or personal information must clearly be fictional demo data.

==================================================
12. ACCESSIBILITY
==================================================

Build accessibility into the experience.

Include:

- Sufficient colour contrast
- Large, clearly spaced touch targets on mobile
- Visible focus states
- Semantic HTML (proper heading hierarchy, landmarks)
- Accessible form labels
- Meaningful button and link labels (not "click here")
- Error messages associated with their relevant form fields
- Alt text for images/icons
- Do not rely on colour alone to communicate status
- Keyboard-accessible navigation and interactions

==================================================
13. TECHNICAL OUTPUT
==================================================

Create ONE complete, self-contained HTML file.

Requirements:

- HTML, CSS, and JavaScript must all be contained in the same file
- No external libraries
- No frameworks
- No external fonts
- No external APIs
- No external images
- No server
- No build process
- Must open directly in Microsoft Edge or Google Chrome
- Fully responsive design, optimised for desktop but working well on tablet and mobile
- All navigation, anchor links, accordions, toggles, and forms must work
- Use CSS and inline SVG where useful for visual elements and icons

The final output must be immediately executable as an HTML file.

==================================================
14. QUALITY BAR
==================================================

Before finalising, evaluate the landing page against these questions:

VALUE
Can a new visitor understand the value within 5 seconds of landing?

CLARITY
Is it obvious what the visitor should do next, at every point on the page?

REALISM
Does this look and behave like a real, professionally built landing page?

FOCUS
Does every section have one dominant message and purpose?

COPY
Could a real target customer understand and be persuaded by the language without additional explanation?

INTERACTION
Do the important interactions (nav, forms, accordions, toggles) actually work?

TRUST
Does the page feel credible and trustworthy without becoming salesy or bureaucratic?

CONSISTENCY
Are terminology, colours, interaction patterns, spacing, and CTAs consistent throughout?

SIMPLICITY
Can anything unnecessary be removed without losing persuasive power?

VISUAL QUALITY
Would this be credible in a professional user test, A/B test, or stakeholder presentation?

If any answer is no, improve the landing page before returning the final result.

==================================================
15. PRODUCT-SPECIFIC CONTENT
==================================================

Now apply all instructions above using the following detailed concept:

[PASTE DETAILED DESCRIPTION OF THE IDEA, FEATURES, OFFER, PRICING, TESTIMONIALS, OR BUSINESS CONTEXT HERE]

If some details are missing, make sensible UX and copywriting assumptions that support the core concept rather than adding unnecessary sections.

Prioritise demonstrating the core value proposition and driving the primary conversion goal over completeness.

==================================================
FINAL OUTPUT
==================================================

Return the complete working HTML landing page.

Do not return a wireframe.

Do not return only a content/copy specification.

Do not explain how someone else should build it.

Actually build the page.

The result should be polished enough that I can open it in a browser and say:

"Imagine this is our real landing page. Please browse it as you naturally would and tell me if you'd take the next step."
```

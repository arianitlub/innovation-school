# PROMPT 4.3.3: Test Results Analysis & Insights

Use Case: Analyzing prototype test results and extracting insights

Note: the original booklet numbers jump from 9 to 11 in this prompt (there is no section 10). Kept as in the source.

```text
I completed prototype testing with [NUMBER] participants. Now I need to analyze results and determine next steps.

WHAT I TESTED:
- Solution concept: [YOUR SOLUTION]
- Key hypotheses: [LIST HYPOTHESES]
- Number of participants: [NUMBER]
- Type of prototype: [e.g., clickable mockup, paper prototype, functional prototype]

TEST RESULTS DATA:

QUANTITATIVE DATA (if you tracked these):
[INSERT YOUR METRICS - e.g., task completion rate, time to complete, error rate, satisfaction scores, behavioral metrics]

QUALITATIVE OBSERVATIONS:
[Paste notes about what you observed: hesitations, confusion points, delights, frustrations, patterns across participants]

PARTICIPANT QUOTES:
[Paste key quotes from participants]

ISSUES IDENTIFIED:
[List specific problems users encountered]

Help me analyze these results:

1. HYPOTHESIS VALIDATION
   For each hypothesis tested:
   - Original hypothesis
   - Evidence for (supporting data and observations)
   - Evidence against (contradictory data)
   - Validation status: VALIDATED / PARTIALLY VALIDATED / INVALIDATED / INCONCLUSIVE
   - Confidence level in this conclusion
   - Implications (what this means for the solution)

2. USABILITY ISSUES - SEVERITY CLASSIFICATION (if applicable)
   Classify all issues found:

CRITICAL (Must fix before launch):
   - Blocks task completion
   - Causes data loss or errors
   - List specific issues with this severity

HIGH (Should fix soon):
   - Major friction, but workaround exists
   - Affects significant portion of users
   - List specific issues

MEDIUM (Fix if time/resources allow):
   - Minor friction, doesn't block progress
   - Affects fewer users
   - List specific issues

LOW (Nice to fix eventually):
   - Cosmetic or minor inconvenience
   - List specific issues

3. PATTERN ANALYSIS
   - What issues occurred with multiple participants? (frequency)
   - What issues caused strongest emotional reactions? (intensity)
   - Which screens/steps had most problems?
   - Which parts worked well?

4. ROOT CAUSE ANALYSIS
   For major issues, identify root causes:
   - Is it UX/design problem?
   - Is it copy/communication problem?
   - Is it conceptual (users don't understand the model)?
   - Is it technical performance?
   - Is it missing functionality?

5. USER SENTIMENT ANALYSIS
   Overall reaction:
   - What % were enthusiastic?
   - What % were skeptical or negative?
   - What % were neutral/indifferent?

Emotional journey through prototype:
   - Where did they feel confident?
   - Where did they feel confused?
   - Where did they express frustration?
   - Where did they express delight?

6. VALUE PROPOSITION VALIDATION
   - Did users understand the core value?
   - Did they see it as valuable/desirable?
   - Would they actually use this?
   - How does it compare to current solution?
   - What would make them adopt it?

7. UNEXPECTED INSIGHTS
   - What surprised us?
   - What did users say/do that we didn't expect?
   - New pain points discovered?
   - New opportunities identified?

8. SEGMENT DIFFERENCES
   - Did different user types have different experiences?
   - Did tech-savvy users have different issues than less savvy?
   - Did younger vs. older users react differently?
   - Implications for design?

9. PRIORITIZED CHANGES FOR NEXT ITERATION
   What to fix/change? Where to go back to in design thinking process?

What to keep as-is:
    - [Things that worked well]

What to add:
    - [Missing features/content]

11. GO/NO-GO DECISION
    Based on testing:
    - Should we proceed with this concept? (YES/NO/ITERATE)
    - Confidence level in proceeding
    - What evidence supports this decision?
    - What concerns remain?

12. RISKS & OPEN QUESTIONS
    - What are we still uncertain about?
    - What needs more testing?
    - What assumptions are we still making?
    - What could go wrong if we build this?

13. NEXT STEPS RECOMMENDATION
    - Build next iteration of prototype? (what changes?)
    - Test with more users? (how many, which segments?)
    - Build functional MVP?
    - Pivot to different approach?
    - Additional research needed?

14. STAKEHOLDER COMMUNICATION
    Key messages for stakeholders:
    - Top 3 findings (most important learnings)
    - What this means (implications)
    - What we recommend (next steps)
    - What we need (resources, decisions)

OUTPUT FORMAT:
Comprehensive analysis report with:
- Executive summary (top findings and recommendation)
- Hypothesis validation summary
- Prioritized list of issues with severity
- Root cause analysis
- Sentiment analysis
- Prioritized changes for next iteration
- Go/no-go recommendation with rationale
- Next steps

Maximum 2000 words with clear sections and tables.
```

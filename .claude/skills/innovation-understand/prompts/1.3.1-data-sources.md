# PROMPT 1.3.1: Data Sources & Availability Mapping

Use Case: Identifying what data you need and where to find it

```text
I am starting a data analysis project for my innovation challenge:

"[INSERT YOUR CHALLENGE HERE]"

Context:
- Problem area: [e.g., customer retention, process efficiency, service quality, cost reduction, employee experience, compliance, sales effectiveness]
- What I'm trying to understand: [e.g., why customers churn, where operational bottlenecks occur, what drives satisfaction, why sales conversions are low]

I need help identifying what data to collect and where to find it. I'm not sure yet what data exists or what would be most useful.

Help me systematically identify relevant data sources:

1. WHAT DATA MIGHT BE RELEVANT?

   Based on my challenge, suggest:
   - What TYPES of data would help me understand this problem?
   - What would tell me about the current state?
   - What would help me understand causes and effects?
   - What would show impact and outcomes?

   Consider different data categories:
   - Customer/user data (who is affected?)
   - Behavioral data (what do they do?)
   - Outcome data (what results occur?)
   - Operational data (how do processes perform?)
   - Financial data (what are the costs/revenues?)
   - Feedback data (what do people say?)
   - Competitive data (what do others do?)

2. WHERE MIGHT THIS DATA EXIST?

   For each type of data suggested, help me identify:
   - Which internal systems might have it? (CRM, data warehouse, operational systems, etc.)
   - Which teams/departments typically own this data?
   - Is it structured data (databases, spreadsheets) or unstructured (documents, emails)?
   - Does it exist currently, or would we need to start collecting it?
   - Is it regularly updated or historical only?

3. WHAT WOULD BE MOST VALUABLE TO COLLECT FIRST?

   Help me prioritize:
   - Which data would give me the most insight into my challenge?
   - What's the "Quick Win" data? (easy to get, high value)
   - What's the "Critical" data? (hard to get but essential)
   - What's "Nice to Have" but not essential?

   Create a priority matrix: Impact (High/Med/Low) × Accessibility (Easy/Med/Hard)

4. WHAT TIME PERIOD AND GRANULARITY DO I NEED?

   Guidance on:
   - How far back should I look? (1 month, 6 months, 1 year, 3 years?)
   - What level of detail? (daily, weekly, monthly, by transaction?)
   - What sample size is sufficient?
   - Trade-offs between historical depth and recent relevance

5. WHAT QUESTIONS SHOULD I ASK DATA OWNERS?

   When I approach teams for data, what should I ask:
   - About data availability and format
   - About data quality and completeness
   - About privacy/security constraints
   - About refresh frequency
   - About how they currently use this data

6. WHAT DATA MIGHT BE MISSING?

   Help me identify gaps:
   - What critical data might not exist yet?
   - What would I need to set up to track going forward?
   - What proxies could I use if direct data isn't available?
   - What external data sources might supplement internal data?

7. HOW SHOULD I ORGANIZE DATA COLLECTION?

   Suggest:
   - A data collection plan/checklist
   - Sequencing (what to get first, what can wait)
   - How to document data sources and methodology
   - How to store and organize collected data

8. WHAT EXTERNAL/COMPETITIVE DATA IS RELEVANT?

   Suggest publicly available data:
   - Industry benchmarks and reports
   - Competitor information (annual reports, websites, app stores)
   - Market research and surveys
   - Regulatory or government data
   - Academic studies

9. EARLY WARNING: COMMON PITFALLS

   What to watch out for:
   - Data quality issues to check for
   - Privacy/GDPR considerations
   - Biases in historical data
   - Missing or incomplete records
   - Definitions that vary across systems

10. SUCCESS CRITERIA FOR DATA COLLECTION

    How will I know I have enough data to proceed with analysis?
    - What coverage is sufficient?
    - What quality checks to run?
    - When to stop collecting and start analyzing?

OUTPUT FORMAT:
Structured guide with:
- Data types to seek (with rationale for each)
- Where to find each type (specific systems/teams)
- Priority matrix (what to get first)
- Data collection checklist
- Questions to ask data owners
- Common pitfalls to avoid

Make recommendations specific to my challenge area while acknowledging I may need to adapt based on what's actually available in my organization.
```
